# IP753 0.6.5 换屏与天气修复

日期：2026-10-26。包名 `xyz.i4o.uni.launcher`，本地版本 `0.6.5+16`。最终签名包已覆盖安装至 IP753；保留用户布局、应用重命名和外观选择。原始录屏、状态、账号及车辆信息仅保存在 Git 忽略目录 `car-reports/20261026-065/`。

## 换屏与地图

- 旧动画在开始/结束时改变卡片外层控件类型，导致原生地图子树反复销毁。现在保持动画层及卡片的挂载身份，通过 SlideTransition/FadeTransition 更新渲染属性，不逐帧重建整个页面栈。
- 缓存纹理加入/移除时同样必须保留原生地图层的 key；新增测试直接模拟原生视图的创建/销毁和地图状态回调，验证预览到达、加载和恢复均不重新创建地图。
- 导航 Surface 不参与工作区动画。换屏先通过专用平台调用隐藏它，确认完成后再改变 Flutter 页；快速反向换屏和返回首页用请求代次隔离旧响应，不发布整份车辆快照。
- 使用内存中的 PixelCopy/Flutter Texture 覆盖地图恢复期间的空 Surface，像素缓存不写文件、不混入周期性 JSON。纹理写入在后台线程，恢复延后到入场布局之后；首帧没有缓存时使用主题色加载占位。隐藏页面停止刷新，释放视图时释放纹理。
- 预热车辆线稿图片，共享互不重叠卡片的毛玻璃背景采样，减少第一屏进入车辆屏时的图片解码与重复模糊。

实车短测连续 6 次往返：最终构建的 `viewId=0`、`displayId=109` 保持一致，返回首页可恢复 ready；旧版记录中的视图 ID 持续变化。录屏按 30fps 采样 396 帧，指定地图内容区没有出现近乎全黑帧。这只是该片段的检查，不能证明所有设备生命周期场景都无闪烁。

同类带录屏的 Android `gfxinfo` 样本中，原生窗口帧耗时 P50 从 500ms 降到 32ms，P90 从 1250ms 降到 93ms；仍有慢帧，且这些不是 Flutter 完整帧率指标。恢复期间仍有加载占位，**换屏的主观流畅度、冷启动和长期表现尚未标记完全通过**。

后续暖态复测时前台已切到全屏导航/影像，随后为其他应用；已停止远程点击，该段 `warm.mp4` 不作为桌面验收证据。停车后需要再次确认滑动、地图返回、设置页/弹窗遮挡和前后台恢复。

## 壁纸

隐藏“叠加主题渐变”开关，移除对应持久化项，忽略旧配置中的 true。图片壁纸在桌面直接显示；“主题渐变”背景本身、主题色、智能调色和保障设置页可读性的背景处理继续保留。已有壁纸不需要用户重新选择。

## 天气

原车当前天气保留 `area=闵行区`、`city=上海市`，不能只把区名交给地理编码。候选地点按行政名称、所属省市、国家、坐标与行政类别匹配，拒绝同音村落和名称前缀误匹配。区县未匹配才回退到所属城市，详情显示实际地区及“城市预报”，失败重试与错误提示也已区分原因。详见 [天气接口说明](OFFICIAL_WEATHER_API.md)。

实车最终已收到 7 天 Open-Meteo 预报，位置为上海市 `(31.22222,121.45806)`，`forecastCityFallback=true`。详情已查看“上海市 · 城市预报”、今天/明天/后续五天及来源文案。它是城市级第三方预报；当前闵行区实况仍来自原车服务，不将其描述为原车区县多日预报。
