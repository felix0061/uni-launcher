# IP753 0.6.10 卡片拖放与缩放

包名 `xyz.i4o.uni.launcher`，版本 `0.6.10+21`。本轮在本地和 Android 9 模拟器验证，没有安装或操作车机。

## 交互

- 红绿灯的左转、右转、直行、掉头使用独立 SVG，线宽统一为 3.2 / 32；普通返回、前进等图标保持原有设计。
- 长按卡片进入编辑并继续拖动，或拖动编辑条移动。卡片提起时有阴影和轻微放大，目标位置显示网格轮廓。
- 停留在占用位置约 150 ms 后，目标卡片移到空位或源卡片腾出的位置；必要时联动调整周围卡片。同尺寸满屏卡片可交换位置，大卡片可同时让多张小卡片让位。不会删除目标卡片，也不擅自改变其他卡片的尺寸、名称或布局类型。
- 邻卡移动使用 150 ms 的缓出动画，松手后拖动预览在 180 ms 内吸附落位。求解失败显示无效落点，释放后回到原位。系统减少动态效果时关闭位移动画。
- 同一手指在左右边缘停留约 450 ms 换屏，继续拖动并放置。目的页满屏时可将被挤开的卡片交换回源页的空位；不自动创建大量空白页。晚到的换屏回复不能覆盖已经完成的拖放。
- 拖动右下角手柄按单格调整宽、高，实时显示当前跨度并重新排版内容；周围卡片也可让位。最小尺寸沿用各卡片规格，最大到当前页边界。红绿灯支持从 4×2 拖至 4×3、8×3 等合法网格大小。时钟天气等卡片的用户自选布局类型仍保留。
- 临时布局只用于预览；松手才合入编辑布局，点击“完成”沿用现有保存流程。取消单次手势、无法放入或取消整个编辑均可回退。

行为参考 AOSP Launcher3 的临时坐标、重排预览和放下后提交机制；UNI 使用适合 Flutter 自绘卡片的独立实现，没有直接替换原车 Launcher 或系统 Widget 宿主。参考：[CellLayout 的重排与提交](https://android.googlesource.com/platform/packages/apps/Launcher3/+/master/src/com/android/launcher3/CellLayout.java)。

## 实现

- `model/card_reorder.dart`：纯网格求解。先只移动直接冲突项，必要时在源页和目标页内重新安排；按距离优先，受搜索节点上限限制。空间不足先按面积拒绝，不会修改输入列表或丢弃卡片。
- `LauncherController`：分离实际 `cards`、临时 `placementPreview` 和目标状态，预览不进入序列化、编辑备份或本地保存。
- `widgets/desktop_drag.dart`：桌面统一跟踪指针；被拖动卡片换父节点、调整大小或跨屏后，手势仍可继续。先把屏幕坐标换算成 1600 单位画布坐标，再计算网格跨度，解决分辨率缩放下的落点偏移。
- `Desktop`：邻卡使用动画坐标；卡片边界使用稳定 GlobalKey 保留子树状态。跨屏单元测试和模拟器均核对了源卡片 Element 不变，尚不代替真实高德跨屏拖动的车机验收。
- 拖动浮层仅在开始时采样一张不超过 150 万像素的缩略图，松手或取消后释放。每次指针移动只更新浮层；重排仅在网格目标变化时计算，不逐帧重建整个桌面或采样地图。底栏不参与浮层移动。正常地图继续使用 0.6.8 的实时纹理。
- 缩放时活动卡片直接按网格跨度更新内容，避免原生地图容器在尺寸动画的每一帧都 resize；其他卡片只动画位置。

## 复现

```sh
cd app
python3 tools/flutter_task.py analyze --no-pub
python3 tools/flutter_task.py test --no-pub
python3 tools/flutter_task.py drive --driver=test_driver/card_reorder_driver.dart --target=integration_test/card_reorder_test.dart --debug -d emulator-5580
python3 tools/flutter_task.py build apk --release --target-platform android-arm64,android-x64 --split-per-abi
```
