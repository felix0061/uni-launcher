# 下一轮 IP753 实车验证

目标设备：领克 05 PHEV / IP753 / Android 9 / `AP_IHU_CN_IP753_21082602`。模拟器通过只代表 App 界面与标准 Android 链路通过，设备验收另行记录。

## 首轮设备检查

1. 安装 `app/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`（当前 Flutter 0.4.0，核对构建报告的 SHA-256），先作为普通应用打开。记录可用窗口大小、密度、底部常驻系统区域、返回与恢复行为。
2. 设置 → 功能接入确认演示已关闭；无来源时保持 `—` 和禁用状态。设置中的原车通信原因应真实反映框架/权限状态。
3. 核对本车 `ecarx.launcher3` 与相关原厂应用的版本、签名、导出入口；样本是 2023 年 Launcher，不能直接当作车内 2021 固件的同一版本。
4. 枚举 `dumpsys appwidget`，对照 `analysis/official-widgets.json`。逐一绑定导航、媒体、天气、日历、账号、清理、胎压；有 AQI 能力时再加入空气质量。
5. 播放原车音乐并授权媒体访问，检查切源/暂停/切歌回调、曲名/歌手/封面/操作权限；确认标准会话是否与原厂当前音源一致。
6. 分别测试窗口导航栏开关、具备授权时的全局开关及原值恢复；检查原车空调区域、倒车接管和从其他应用回桌面。360 仅使用官方已启用且可访问的 AVM Activity。

## 补齐统一卡片与车控所需材料

需要提供者 APK 或设备侧接口/RemoteViews 观测，建立逐卡映射。记录原厂提供者与版本、完整字段、原始值、单位/精度、有效与空值、更新时间和点击动作；再对照新卡片同值快照。兼容原厂 Widget 可用，不等于统一视觉卡片的数据解析已经通过。

空调先读取本车实际框架的方法/权限/支持项，建立 `VehicleAdapter` 的只读状态与回调；核对温度量程、步长、编码、风量与模式。之后逐项实现可逆操作、命令超时与回读确认，最后验收断开/恢复。当前模拟器版的直接车控仍不可用。

导航摘要、地图嵌入、PHEV 电量/续航等单独确认来源。原 Launcher 未提供完整字段的部分，不以第三方天气、示意路线或其他车型属性替代原厂值。

设备记录保存在本地独立目录，原 APK、账号内容和设备日志不作为源码提交；原创适配器、脱敏字段契约和验证结论以 Git commit 管理。

## 0.4.0 待上车验收

本轮完成项与差距见 [官方能力对照](OEM_PARITY_0_4.md)。本轮未连接车辆。

1. 核对包版本/签名与 `INJECT_EVENTS`、嵌入权限，选择本车高德，观察卡片画面、双指缩放、拖动、全屏返回、编辑/删除释放、休眠和倒车接管。普通签名包声明权限不代表系统已授予。
2. 关联实际安装的网易云、QQ、原车媒体，分别播放/暂停/切歌，核对标题、作者、封面、歌词与当前音源；选中的应用没有会话时应保持不可用。
3. 车辆详情复制只读结果，逐字段与原车屏幕比较温度、风量、模式、三项座椅和四轮胎压；特别核对压力单位及无效/静止/刚上电状态。当前版本不发真实车控。
4. 断开/恢复原车服务后，旧值超过 5 秒应失效；恢复后重新读取，不重放操作。
5. 取得天气/账号/日历/清理/AQI/车辆 Provider 的字段契约，再完成原厂同值验证；PHEV 电量/续航/里程暂不猜接口。

可先只读采集（不自动执行）：

```sh
python3 tools/collect_car_readiness.py --serial <车机序列号> --out car-reports/first-0.4.0
```
