# UNI 语音 · 界面布局与语音链路规划

> 车机使用场景：1920×1080、驾驶中只能扫一眼、绝大多数操作是"选中一个音色试听"。
> 原则：**一屏看全、按钮够大、层级只分三层（状态 / 内容 / 高级）**。

要点：

- **顶栏常驻**：状态胶囊 + 总开关 + 一行引擎/权限说明，任何一栏滚动都不影响它。
- **左栏 42%：状态与配置**。对话记录固定 130dp 内部滚动，不会把整栏撑空。
- **右栏 58%：音色主场**。466 个音色用 RecyclerView 虚拟化 + 4 列网格，
  按性别/中英文/热门筛选，点一下即选即试听（直接播官方试听链接）。
- **底部留 150dp**：桌面底栏常驻在窗口之上，设置页内容不能压到它下面。
- **配色**：底 #0B0E13 / 卡 #151A22 / 线 #232A36 / 强调 #4CC2FF，夜里不刺眼。

音色数据：`assets/volcano_voices.json`（466 条，165KB，随包固化，来自官方
ListSpeakers 导出），字段只留展示与试听需要的部分，不再走网络接口。
## 二、语音链路（现状）

```
唤醒词(KWS) ──命中──> 聆听(LISTENING) ──VAD 断句──> 识别(THINKING)
                                                        │
                        ┌───────────────────────────────┤
                        │ 本地规则命中 → 车控（桌面执行）│
                        │ 天气/车况 → 本地能力           │
                        │ 都不是 → 云端 LLM 闲聊          │
                        └───────────────┬───────────────┘
                                        ▼
                                   播报(SPEAKING)
                                        │ 播完立刻
                                        ▼
                          聆听(连续对话) ──6s 无话──> 待机(等唤醒词)
```

关键约束：

- 唤醒瞬间申请 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`，音乐/导航自动压低；退下时还原。
- 通话中（`MODE_IN_CALL / MODE_IN_COMMUNICATION`）完全不抢麦克风、不识别。
- 连续对话里只接"对助手说的话"：带称呼/疑问/指令特征，且长度 ≤ 26 字；其余当环境声，静默退回聆听。
- 播报有看门狗（1.5s + 320ms/字，封顶 20s），合成引擎不回调也不会卡在"回复中"。
- 车控只走本地规则或云端白名单 JSON，云端永远不直接碰车辆接口。

## 三、还能再优化的小细节（按收益排序）

1. **ASR 置信度门限**：sherpa 的 `getResult` 带 token 概率，低于阈值直接当噪音，比现在的长度启发式更稳。
2. **唤醒词二次确认**：误唤醒时先播一声极短的"嗯？"，用户不说话就不进入聆听，省电也省尴尬。
3. **打断（barge-in）**：播报中检测到人声 → 立刻停止播报转聆听，车机上体验提升很大。
4. **TTS 预合成**：固定话术（"好的"、"已调到…"）预生成 PCM 缓存，首字延迟从 ~600ms 降到 ~50ms。
5. **火山 WS 会话复用**：现在每句开一次 WS，改成一条连接多句复用，省 RTT。
6. **对话记录落盘**：现在只在内存里，服务重启就没了；写到 prefs 里保留最近 50 条。
7. **本地音色与火山音色统一成一份清单**：界面只呈现"音色"，实现细节（本地/云端、模型/接口）对用户透明。
8. **导航语音让路**：导航播报时暂停唤醒 1.5s，避免把导航指令当指令。
