# 新桌面产品与界面设计

暂名 **LYNK 05 / DRIVE**。定位是“导航看得清，音乐随手控，原车功能始终可达”的领克 05 车机桌面。首期针对 IP753 / Android 9，参考既有照片的 1920×1080 整屏尺寸；原车状态栏、空调栏和 Android 实际 density / Insets 必须上车确认，所有标注为设计基准而非测量结果。

## 1. 首页布局

```text
┌────────────── 时间 / 品牌 / 天气 / 连接状态 ───────────────┐
│ ┌────────────────────────────────┐ ┌────────────────┐ │
│ │ 下一步转向 / 路口距离            │ │ 正在播放        │ │
│ │                                │ │ 封面 / 歌曲     │ │
│ │          导航主区域              │ │ 歌单 / 进度     │ │
│ │       地图或导航摘要             │ ├────────────────┤ │
│ │                                │ │ 天气 / 温度     │ │
│ │ 到达时间 / 剩余时长 / 距离       │ │ 城市 / 短时预报 │ │
│ └────────────────────────────────┘ └────────────────┘ │
│ ┌──────────────── 96px 毛玻璃统一底栏 ────────────────┐ │
│ │首页/全部│空调操作│播放控制│音乐信息│车辆信息│360影像│ │
│ └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

V04 延续无左侧栏设计，屏幕左右留边 32 设计像素、卡片间隔 24。第一页导航占 8 列，音乐与天气占右侧 4 列；第二页放账号、清理、日历及胎压，覆盖 IP753 的七类默认官方卡片。用户可自由编排。底栏保留应用入口，桌面设置通过长按首页进入，不额外占用图标。

地图未验证嵌入能力时，实际首版显示导航摘要或兼容 Widget；原型展示后续地图形态。点击导航打开原导航应用。应用抽屉最多首屏 12 项，名称保持一行/两行可读，不以无限小图标填满屏幕。

底栏为 96 设计像素高，严格按“首页、全部 → 空调操作 → 音乐控制 → 音乐信息 → 车辆信息 → 360 影像”排列。空调提供温度加减、风量入口与开关；音乐控制位于歌曲信息之前。按钮仅用图标，保留温度及歌曲数据文字。首页短按返回，长按 650ms 进入设置，首页空白处长按同样进入设置。原车现有底栏的窗口归属与可调整性仍需实车核对，目标布局不等于已经能替换原车栏。

## 2. 视觉语言与主题

现代科技感来自清晰的几何、稳定网格、细线图标和少量青绿色状态提示。沿用方案 A 配色，将主要内容面改为半透明毛玻璃：深色烟灰、浅色乳白，背景为低饱和青灰渐变，圆角 28，以细亮边和柔和阴影区分层次。关键文字保持不透明。Android 9 的实现方式与性能验证见 [视觉方向说明](../design/VISUAL_DIRECTION.md)。

| Token | 深色「夜航」 | 浅色「晨光」 | 使用 |
| --- | --- | --- | --- |
| background | `#10161D` | `#F3F5F4` | 桌面主底色 |
| surface | `#1A242D` | `#FFFFFF` | 音乐、抽屉、弹层 |
| surface-subtle | `#24313A` | `#E9EFEC` | 次级按钮、封面背景 |
| text-primary | `#F2F6F5` | `#182D29` | 歌名、转向、温度 |
| text-secondary | `#ADBDC4` | `#546C65` | 来源、距离、次要标注 |
| accent | `#71E4CE` | `#087568` | 路线、已选、主要动作 |
| accent-text | `#102E28` | `#FFFFFF` | 强调色按钮文字 |
| divider | `#35444D` | `#DCE5DF` | 必要的结构分隔 |

主题三档：跟随车辆/系统、浅色、深色。自动档先跟随系统 `uiMode`；ECARX 亮暗状态只在映射确认后参与。抖动防护采用延时和最短保持时间，具体阈值上车调整；手动选择优先保留。切换时保留导航、媒体、弹层和温度状态，以 160–220ms 过渡表层颜色，地图按其来源能力单独协调。

配色独立于深浅模式，预置青屿、冰川、鸢尾、琥珀、玫瑰五组；取色器和 HEX 输入支持自定义种子色，派生深浅强调色与氛围背景。默认 token 表对应青屿；其他色值及交互规则见 [V04 视觉规范](../design/VISUAL_DIRECTION.md)。设置采用顶部标签，通过长按首页进入。

外观设置提供 0–40px 的圆角滑杆与数值输入，默认 28px、步长 1，0 对应直角。圆角应用于主要卡片、底栏与面板，次级控件按比例派生；保留圆形色点及图标语义。演示立即预览并本地保存，边界输入已校验。这里的像素为设计画板单位，后续按车机密度适配。

主题设置右侧实时预览栏提供“毛玻璃”开关，`preferences.glass` 默认 `false`。关闭时保留半透明底色、边缘和阴影，开启时增加背景模糊；浏览器桌面、缩略预览与弹层同步，并本地保存。此开关仅控制设计预览模糊，默认值与语义对齐 Flutter 新增设置；不表示车机平台模糊能力已经验证。

图标使用 2px 线宽的原创单色符号；Android 实装统一矢量资源。基准信息 28–32 设计像素，主指令 40–52，温度 44–56；基于实际 density 换算为 sp/dp 后实车校准。字号不只按 1920 像素等比缩放。触控关键区至少 64dp，密集次级操作至少 48dp，整车坐姿验证后调整。

## 3. 导航组件

- 未导航：展示目的地入口和最近目的地，地图不可用时仍可打开导航；地址内容由用户维护，不预设真实家庭/公司坐标。
- 导航中：下一转向、路口距离为最高层级；剩余时间、距离、到达时间次之。车道信息仅在来源有效时显示。
- 转向指令变化：只更新相关区域；导航播报时保留音量焦点规则，桌面不再次播报相同指令。
- 数据停止：清除“下一步正在发生”的视觉强调，标注导航状态未更新；保留打开原导航的入口。
- 地图嵌入失败：自动回退摘要视图；恢复嵌入时不重新发起路线、不重置目标应用任务。

后续交互原型再加入导航/未导航、地图/摘要切换；当前先用静态导航画面评审风格。示意路线不是可用地图数据。

## 4. 音乐组件

底栏固定显示封面、歌曲、歌手/音源及上一首、播放/暂停、下一首；右侧音乐大卡显示更丰富的封面、歌单与进度，共用同一媒体状态，首页只在底栏呈现三键播放控制。控件按会话返回的 actions 决定是否可点；不支持 seek 时只显示进度。点底栏歌曲区域展开音乐详情；详情保留打开播放器的入口，点音源进入有限选项菜单。

音源与原车媒体中心的当前选择一致；任何替代会话方案必须先核对其元数据和操作与原车卡片相同。导航 TTS 不切换成音乐主音源；蓝牙通话进入时不自动抢焦点。断连时停止进度推算，显示最近缓存与“未连接”，不把按钮按下视为播放成功。演示中底栏、大卡和音乐详情共用播放/曲目状态。

## 5. 空调与车辆组件

完整空调层包括主驾/副驾温度、风量、AUTO、A/C、SYNC、内外循环，以及前后除霜入口。当前浏览器座舱舒适弹层补齐主驾座椅加热、主驾通风、副驾加热，副驾不添加通风；入口沿用空调，底栏不新增图标。正式车控次序为：点击 → 提交中 → 服务结果 → 对应状态回调确认；失败还原显示并解释“未生效”。

座椅三项分别显式选择“关闭 / 1档 / 2档 / 3档”，对应 `ui.climate.driverHeat`、`driverVent`、`passengerHeat`，初始均为 0。浏览器动作约定为 `seat-heat` + `data-zone="left/right"`、`seat-vent` + `data-zone="left"`，`data-value` 为 `0`–`3`。主驾加热非 0 时通风归 0，通风非 0 时加热归 0；关闭只改当前项，副驾加热独立且不随温度 SYNC 联动。按钮采用原创纯线图标、当前青绿主题色及卡片圆角 × 0.64，选中态与共享状态一致。

以上档位和互斥仅为演示数据，实际档位范围、编码、能力与服务契约待实车确认。独立气候研究稿扩为 900×720，空调与座椅同时可见；主弹层在 1920×1080 内展示，导图与渲染尺寸同步更新。浏览器不发送座椅或空调车辆指令。

UI 温度以摄氏半度为展示单位，但硬件范围、LO/HI 和不可用值均由车型能力决定。不得将样本中的 2 倍编码理解为所有车型通用量程。拖动连续控件仅提交合并后的目标值，并对同一车控串行执行。

胎压是车辆页的首个只读信息卡。对无效值显示“—”，区分“未提供”与“0”；确认四轮顺序、单位与更新时间后再给正常/异常判断。PHEV 电量/续航留待后续明确接口后启用，首页不放无法验证的能量数字。

## 6. 页面与交互

| 层级 | 页面/层 | 主要操作 |
| --- | --- | --- |
| 主层 | 首页 | 看导航、切歌、进入空调、打开常用应用 |
| 主层 | 应用抽屉 | 启动、收藏、排序；保留官方设置和原桌面入口 |
| 主层 | 车辆 | 胎压与已验证的车辆信息 |
| 浮层 | 空调 / 座舱舒适 | 温度、风量、A/C、主驾加热/通风、副驾加热；返回关闭浮层 |
| 浮层 | 音源 | 有限的有效媒体源 |
| 次级 | 桌面设置 | 外观主题、五组/自定义配色、卡片布局、功能接入 |
| 编辑层 | 卡片编辑 | 添加、拖动移动、角点缩放、编辑内容、删除/撤销、取消/完成 |
| 浮层 | 原车卡片库 | 媒体、导航、天气、日历、账号、清理、胎压、按车型空气质量；扩展卡单列 |
| 浮层 | 音乐 / 车辆 / 360 | 共享音乐状态、四轮胎压占位、真实影像接入前的等待界面 |

桌面采用 12×6 网格，调整大小时吸附并阻止重叠。导航最小 6×3、胎压 4×3、账号 3×3，其余至少 3×2。卡片可重复添加，空间不足时新增页；页数独立持久化，空白页刷新后保留。删除支持撤销；取消同时恢复卡片和页数，完成保存。底栏应用入口及首页长按设置始终可达。正式 Android 的行车中编辑限制随实际车辆状态接入确认。

原车卡片统一使用对应官方提供者，字段、单位、精度、空值、失效状态、更新时间与动作语义均需保持一致。完整覆盖表见 [官方组件索引](../analysis/official-widgets.json)。目前缺少提供者 APK 和实车卡片内容，字段一致性尚未验证；天气不再预设未经证实的降雨/空气指标，清理和账号不虚构统计值。浏览器天气城市仅为样式示例；正式版本城市与原车来源保持一致。

返回键优先关闭浮层，再退出抽屉/子页，最后回首页。Home 键回首页；恢复桌面不重启导航和音乐进程。实车基线阶段保留系统默认桌面选择与官方入口，不覆盖已有应用包名。

## 7. 当前交付与后续实现

当前交付 V04 双页桌面、九类官方卡片样式总览、指定顺序底栏、长按设置，以及空调/音乐/车辆/影像面板。浏览器支持主题/圆角、卡片编辑、撤销、页面保存与各处状态同步，交互验证结果见 [design-verification.json](../analysis/design-verification.json)。原厂实时字段、设备调用及 Android Launcher 均未实现，仍属于用户要求的设计阶段。

### 歌词与桌面切换补充（0.3.0）

音乐卡片及底栏显示主题色当前歌词，音乐详情显示前/当前/后行并跟随播放位置滚动；暂停停止推进，切歌清空旧词，缺少歌词或时间轴时保留明确空态/手动滚动。仅使用实际音源提供的歌词，原厂来源待实车核对。

设置新增「切换动效」标签：无动画（默认）、淡入淡出、横向滑动。卡片区域按翻页方向切换，底栏和状态区固定；编辑或系统减少动态效果时不执行动画。
